# 0.2.0 / V13 正式混合检索补充执行记录

最新授权：用户要求“继续完成正式混合检索，作为 V13 和 0.2.0 的补充”。这包含通过既有网关建立正式本人材料向量、启用远程检索和持续维护；不新增供应商，不变更应用版本和主库 schema，不改原有导航/入口/展示/筛选及输入框加结果。

原实现、匿名指标与未通过项以 `docs/handoffs/2026-09-10-search-hybrid-delivery.md` 为基线。正式服务启动在 4173，旧匿名预览在 4397。正式数据不作自动化、截图、评测 fixture，不输出正文、身份信息、凭据或网关地址。正式索引仅取现有本人来源白名单，出站投影最小化和身份信息遮蔽；真实索引任务是授权业务维护，不冒充匿名验收。

## Task 1: 规划质量与远程延迟

负责人范围：`server/search-model-adapters.js`、`server/search-query-plan.js`、模型相关测试与独立匿名探针。核实已有网关可用快速模型或现有模型低推理配置，保持 strict json_schema 和本地完整校验、无 SQL，不能以大面积规则回退或只缓存热查询伪造通过。目标匿名60条冷查询 p95≤10秒、整体18秒预算；分别记录模型通过率、回退、规划/Embedding/Rerank耗时。只对匿名材料实际请求；不变更其他既有Agent模型配置。不打印密钥/网关或原始上游错误。必要时输出明确 SEARCH_QUERY_MODEL/配置建议给主线集成。

## Task 2: 正式规模向量召回

负责人范围：`server/search-vector-store.js`、`server/hybrid-search.js` 及向量检索相关测试。解决超过10000资格向量即失效和每查询重复全文件哈希/索引加载的问题。稀疏候选可精确评分；宽查询使用有界迭代 ANN 扩召回，并在本地完整硬条件/排除/来源哈希重新验证，明确 bounded/approximate，禁止向量替代必需条件。保持删除、归档、内容去重、原子代际和分页稳定。索引读写需适合16GB本机，不能全量候选正文常驻。与主线维护共享 store API，变更接口先通知主线。新增持久 worker 如必要由主线协调，不并行修改 service 文件。

## Task 3: 正式回填与持续维护

主线范围：`server/search-vector-maintenance.js`、维护 CLI、服务/启动配置、生命周期测试。增加正式路径显式启用、脱敏聚合 inventory、出站最小化、限流重试、取消、断点恢复/持久缓存、删除/归档同步和状态报告；源库只读、向量索引独立，避免全库网络期间长事务阻碍 WAL。后台维护不依赖 Agent 工具，保留旧 active 代际和失败降级，不把半成品索引标记 ready。回填完成后配置现有正式服务，启用同一链路；无新增 schema 迁移。

## Task 4: 实测、审阅和发布补充

运行相关匿名回归和60条真实远程匿名质量评测，补语义困难用例和大资格范围 ANN/硬条件回归。记录条件、Recall@50、Precision@10、nDCG@10、MRR、证据归属、延迟、RSS、索引体积、降级和模型通过率。沿用UI并验证受影响状态，不把之前成绩说成本轮新结果。审阅最终差异，保留全部原用户修改；按指纹带回正式目录，安全重启，核对 remote/vector/rerank 实际状态及维护生效。更新0.2.0补充文档与脱敏正式索引记录；旧证据保留为历史。
