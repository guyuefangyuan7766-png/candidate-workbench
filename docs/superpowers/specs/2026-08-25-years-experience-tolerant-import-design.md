# 工作年限宽容导入与原文展示设计

> 状态：方案稿，待 Claude Code 实施。本文不代表功能已经发布，也不授权直接修改正式数据库或用户原始 Excel。

## 背景

最近的北森人才库导入暴露出一个数据契约问题：`工作年限`不是稳定的数字列。真实来源中同时出现 `3`、`3年6个月`、`三年半`、`应届`、`经验不详`、范围值和带说明文字的值。

当前实现有三处会损失来源信息或阻断导入：

- `server/validation.js` 的 `normalizeYears()` 只提取第一个阿拉伯数字；没有数字时返回 `null`。
- 同文件的 `sanitizeCandidateInput()` 把无法解析的非空值加入错误，导致整行导入失败。
- `server/database.js`、`src/api.ts` 和若干组件把工作年限当作必然可转成数字的字段，`null` 会被前端默认成 `0`，原文也无法展示。

独立的附件解析入口 (`server/attachments.js`、`src/attachment-candidate-prefill.ts`) 还使用更窄的正则和 `0` 默认值。如果只修文件导入入口，附件导入会继续产生不同口径。

## 用户目标

1. 工作年限字段对来源格式绝对宽容：只要文件行本身合法，工作年限格式不应单独阻断候选人导入。
2. 保存并展示来源原文，不把原文强行转换成 `0`，也不在档案、预览或导出中展示字面量 `null`。
3. 对能安全解释的值保留数值投影，继续支持现有排序和数值筛选；不能安全解释的值只保留原文，不伪造数值。
4. 空值仍表示源文件没有提供工作年限；这与“未知/应届”等非空原文不同。

## 方案选择

采用“数值投影 + 原文事实”双字段，而不是把现有 `years_experience` 直接改成字符串。

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 直接把 `years_experience` 改为 TEXT | 最简单地保存原文 | 破坏排序、筛选、旧 API 客户端和数据库查询 | 不采用 |
| 所有值都转成数字，无法解析时写 0 | 改动最少 | 0 与真实 0 混淆，来源信息永久丢失 | 禁止 |
| 保留数值列，新增原文列 | 兼容旧查询，原文可审计，迁移可加法完成 | API/UI/导出需要同时处理两个字段 | **采用** |

“不要 null”在本方案中的精确定义是：用户可见的工作年限不输出 `null`，而是优先显示原文；真正没有来源值时显示空白。数据库里的数值投影允许为 `NULL`，因为它表示“无法安全数值化”，不是把原文丢掉。原文列使用空字符串表示没有来源值，避免 UI 和导出出现字面量 `null`。

## 数据模型

### 字段契约

| 字段 | 存储 | 语义 | 对外行为 |
| --- | --- | --- | --- |
| `candidates.years_experience` | `REAL`，可空 | 可安全解释的数值投影；用于排序/范围筛选 | `number \| null`，仅作计算字段，不作为主要展示文本 |
| `candidates.years_experience_raw` | `TEXT NOT NULL DEFAULT ''` | 来源工作年限文本；保留非空原文，建议上限 1,000 个字符 | `string`，没有来源值时为 `""` |
| `years_experience_display` | 不落库，序列化计算 | `raw` 非空时为 `raw`，否则把数值格式化成文本；两者都没有时为 `""` | UI、预览、导出使用此值或同等逻辑 |

新增 `years_experience_raw` 采用 V13 幂等加法迁移。基础建表也必须包含该列；旧库迁移不能重建候选人表、删除数据或覆盖已有非空原始信息。对旧记录仅有数值而没有原文时，可回填其规范化数字文本（例如 `3`），不得把缺失值回填成 `0`。

### 写入规则

- 输入字段仍叫 `years_experience`，兼容数字和字符串；导入器不要求调用方新增列名。
- 非空输入先保存 `years_experience_raw`，再尝试生成 `years_experience`。
- 输入为空时，API 的显式清空操作写入 `years_experience_raw = ''`、`years_experience = NULL`；增量导入的空单元格沿用现有“空值不清除”规则，不覆盖数据库已有值。
- 原文列应限制长度并拒绝控制字符扩散，但长度/字符问题不得把同一行变成“工作年限解析失败”；完整源单元格仍保存在导入 `raw_payload` 中供审计。
- 任何路径都不得把“非空但无法解析”转换成 `0`。只有源文本明确表示 0 时，数值投影才是 `0`。

## 解析契约

解析函数建议统一为：

```js
normalizeYearsExperience(value) -> {
  raw: string,              // 空值为 ""
  numeric: number | null,   // 无法安全解释时为 null
  provided: boolean         // 是否有非空来源值
}

formatYearsExperience({ raw, numeric }) -> string
// raw 非空返回 raw；否则 numeric 为有限数时返回不带多余 .0 的文本；否则返回 ""
```

`sanitizeCandidateInput()` 使用该结果写入 `years_experience_raw` 和 `years_experience`；工作年限解析永远不单独产生 validation error。已有 `normalizeYears()` 可以保留为内部兼容包装，但不能继续承担“失败即阻断”的职责。

### 解析边界

数值投影只在表达式含义明确时生成；所有情况下原文都必须保留：

| 输入示例 | 原文 | 数值投影 | 行结果 |
| --- | --- | --- | --- |
| `3`、`3.5`、`3年`、`3 年`、`3 years`、`3 yrs` | 原样文本（去首尾空白） | `3`、`3.5` | 通过 |
| `3年6个月`、`42个月` | 原样文本 | `3.5`、`3.5` | 通过 |
| `三年`、`三年半` | 原样文本 | `3`、`3.5` | 通过 |
| `约3年`、`3年以上`、`3年左右` | 原样文本 | `null`（有修饰词，不制造精确值） | 通过 |
| `1-3年`、`1至3年`、`1 到 3 年` | 原样文本 | `null`（范围不取中值） | 通过 |
| `应届`、`无经验`、`经验不详`、`待核实` | 原样文本 | `null` | 通过 |
| `100年` | 原样文本 | 有限非负数字 `100` | 通过，不按 0 或 80 截断 |
| `-1年`、溢出数字、二进制/对象值 | 可读字符串（或空字符串） | `null` | 通过，记录原文；不做负数推断 |
| 空单元格、空白文本 | `""` | `null` | 通过；增量导入不覆盖已有值 |

规则补充：

- 不从手机号、年份、工作时间段或其他列猜测工作年限。
- 中文数字解析至少覆盖常见的 `一` 至 `十`、`半` 组合；未覆盖的文字直接走原文分支。
- 只接受有限的非负数作为数值投影；`Infinity`、`NaN` 和超出 JavaScript 有限数范围的文本只保留原文。
- 解析器可使用 NFKC 做识别，但 `raw` 的展示文本不能被改写成计算值；完整原始单元格以 `raw_payload` 为最终审计来源。

## 导入与重复数据语义

### 通用导入与北森导入

- `工作年限` 继续作为现有表头别名，不要求用户更改 Excel。
- 预览行只要其他字段通过校验，即使工作年限是任意非空文本也应为有效行；预览中同时返回 `years_experience_raw`/`years_experience_display`，便于人工确认。
- 北森 `应聘者ID` 的增量 upsert 遵循现有非空覆盖、空值不清除规则。后续批次提供新的非空工作年限时更新原文和数值投影；空单元格不擦除旧值。
- 手机号或邮箱冲突仍按现有身份冲突规则阻断，不能被“宽容工作年限”吞掉。
- 导入失败行不写候选人、关系或 `raw_payload`；工作年限本身不再产生失败行。

### 原始载荷

导入 `raw_payload` 继续保存完整源行（包括工作年限原单元格）。`years_experience_raw` 是便于查询和展示的投影，不替代审计载荷，也不应把敏感原始载荷写入公开日志或证据文件。

## API、前端与导出

### API

候选人响应增加 `years_experience_raw` 和计算字段 `years_experience_display`；旧客户端仍可读取 `years_experience` 数值字段。序列化层不能使用 `Number(value ?? 0)`，缺失数值必须保持 `null`，展示字段必须是字符串。

候选人创建/更新请求继续接受 `years_experience` 的数字或文本。内部 `years_experience_raw` 不作为普通用户可任意篡改的独立输入；若需要迁移/导入回放，只能由统一校验层生成。

### UI

- `CandidateForm` 的工作年限控件改为可输入文本，回填优先使用 `years_experience_raw`，不能使用数字 `0` 代替空值。
- `CandidateDrawer`、`PipelineBoard` 和导入预览优先显示原文；明确输入 `0` 时显示 `0`，没有值时显示空白，不显示 `null`。
- 数值排序/筛选继续使用 `years_experience`；数值为空的候选人排在未定义值一侧，不得被当作 0 纳入范围。
- 附件文本/视觉解析和候选人预填充必须复用同一解析契约，不能恢复 `0` 默认值。

### 导出

现有“工作年限”列保持不变，但导出值优先使用 `years_experience_raw`，没有原文时才使用格式化数值。可选增加内部/分析列时必须单独命名为“工作年限数值”，不得覆盖原文列。

## 迁移与兼容

1. 基础 `CREATE TABLE candidates` 增加 `years_experience_raw TEXT NOT NULL DEFAULT ''`。
2. 在 V12 后增加 `migrateV13Database()`，使用 `ensureColumn` 和幂等迁移记录 `13, 'candidate_years_experience_raw'`。
3. 迁移回填仅处理 `raw` 为空且 `years_experience` 非空的记录，使用不带多余小数的数字文本；不把 `NULL` 变成 `0`。
4. 旧 API 响应缺少新列时，前端按 `raw = ''`、`display = formatted numeric or ''` 兼容。
5. 回滚采用“回滚应用代码、保留新增列”的非破坏方式；删除 V13 列只能在另行备份并经批准的离线维护中执行。

## 安全与性能约束

- 原文长度有明确上限；导入解析仍受现有文件、列、单元格和 worker 资源限制。
- 不为原文列添加未经验证的全文索引；若搜索需求增加，先评估现有 FTS 字段政策。
- 不记录姓名、手机号、邮箱、原始载荷或预览 token 到公开测试输出。
- 不修改用户提供的 `.xls`，不在开发验证中写入正式数据库。

## 验收标准

实现完成必须同时满足：

1. V13 在新库和已有 V12 库上幂等执行，旧候选人数、数值字段和迁移记录保持完整。
2. 上表所有样例都能通过 `sanitizeCandidateInput()`；无法解析样例的 `numeric` 为 `null`，但 `raw` 不为空且不为 `"0"`。
3. 通用导入、北森导入、API CRUD、附件预填充和 CSV/XLSX 导出均能往返原文；工作年限格式不再单独导致行失败。
4. 明确的 `0` 显示为 `0`；未知文本显示原文；真实空值显示空白；任何用户可见路径不出现字面量 `null`。
5. 数值排序/筛选对可解析值继续有效，空/文本值不会隐式按 0 参与范围判断。
6. 手机/邮箱冲突、归档候选人、职位关系和其他既有校验行为不回归。
7. 使用用户提供的 `自定义excel7-20caac42-246c-402c-a583-45e991ec30b3.xls` 做只读预览，抽取不超过 100 条有效行，确认非标准工作年限不再生成“工作年限错误”，并确认关联职位、人才库和来源预览统计仍与现有规则一致；不得直接提交到正式库。
8. 更新版本、数据模型、字段映射、导入指南、API、测试、运维和迭代日志；文档明确 V13 尚未发布前不得宣称生产完成。
