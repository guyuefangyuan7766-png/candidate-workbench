# 响应式尺度与导航状态隔离：修改方案（设计规范）

日期：2026-09-15。状态：**方案已定稿，尚未实施**。本轮只交付方案与文档同步，不改动 `src/`、`server/` 代码，不改数据库结构。

适用版本：目标应用版本 `0.3.0`；数据库保持 schema `V13`，无新增迁移。

## 1. 背景：本轮实测到的真实缺陷

证据来自匿名预览库（`tests/browser/anonymous-talent-workspace-server.mjs`，48 位虚构候选人）+ Vite 4400，Playwright 在 15 种视口下逐页实操。原始截图与数据在 `.codex-tmp/audit/`（临时目录，不进入版本控制）。

### 1.1 模块与控件整体过大，且不随分辨率变化

实测 1024×768、1152×864、1280×720、1366×768、1440×900、1536×864、1600×900、1680×1050、1728×1117、1920×1080、2560×1440、3840×2160、768×1024、820×1180、390×844 共 15 档视口，以下数值**一档都没变**：主标题 `34px`、侧栏导航 `16px`、表头 `16px`、数据行 `≈72px`、列表头像 `52px`、指标数字 `28–34px`。

后果：

- 1366×768 笔记本开 125% Windows 缩放（CSS 视口 1093×614）时，工作台首屏只剩 4 个指标卡和半个分布卡，指标卡被挤成两列且单卡高约 120px。
- 1366×768 下候选人列表首屏只显示 5 行，标签列每行换行成三行高。
- 2560×1440 / 3840×2160 上所有字号与 1536 相同，大屏显得过小。
- 全站只有 `@media (max-width: 720px)` 一个尺度断点（只把 `h1` 降到 20px）和 `@media (min-width: 1440px)` 一个布局断点（并排抽屉），**721–1439px 这一段（最常见的笔记本区间）没有任何适配规则**。

### 1.2 常见分辨率下表格列被裁

- 1024×768 / 1152×864：右侧整列丢失，`地点 / 学历` 被切一半（显示为「杭州 / 硕」），`标签`、`更新时间`、`操作` 三列完全不可见。
- 1366×768：内容区 1158px，表格实际需要约 1030–1250px，`操作` 列仍在视口之外。
- 768×1024：侧栏仍固定 208px（占 27%），内容区只剩 560px。
- 表格列宽用固定 `min-width` 累加（`src/workspace.css` 的 `1477-1490` 行），没有任何按优先级丢弃列的策略；列是否可见只由「是否并排抽屉」一个条件决定。

### 1.3 并排抽屉把正文推出版口（已在上轮记录，本轮并入统一修复）

≥1440px 打开详情抽屉时内容区被压到 848px，而表格需要 1029px（候选人库）／860px（履历检索结果表），`更新时间`、`操作` 列被抽屉遮住，底部分页条右侧也被压住 20px。

### 1.4 导航表面（surface）不互斥，出现「点不开」

实测三个可复现场景：

- **叠加**：点「AI 助手」→ 点「导入候选人」，两个页面**同时**渲染在同一内容流里（导入页从 y=19 开始，拾才助手从 y=692 开始），要滚动才能看到第二个页面。
- **点不开**：点「导入候选人」→ 点「候选人库」，地址栏变成 `/candidates`、侧栏高亮也切到「候选人库」，**但屏幕上显示的还是导入页**，候选人列表被 `hidden` 隐藏。
- **无响应**：上述叠加状态下，再点「导入候选人」或「AI 助手」都不产生任何视觉变化。

根因（`src/App.tsx`）：

- `:1354` `hidden={importOpen || assistantOpen}` 隐藏主内容栈，但导航动作不清除这两个状态；
- `:1350` `onOpenImport` 只做 `setImportOpen(true)`，既不关闭助手也不做 toggle；
- `:646` `openTool()` 同样不关闭导入；
- `:1527`/`:1528` 两个表面并列渲染，没有任何互斥；
- 侧栏高亮 `src/views/AppShell.tsx` 中 `importOpen` 优先于 `toolOpen`，导致「高亮 = 导入、画面 = 助手、URL = /assistant」三者互相矛盾。

助手内部三页（AI 助手 / 履历检索 / 附件解析）互切正常，说明缺的只是 `import` ↔ `tool` ↔ `page` 之间的互斥。

## 2. 目标与非目标

**目标**

1. 全站尺度随视口分档，1024–3840px 内「模块不过大、文字可读、首屏有效行数足够」。
2. 任何受测分辨率下表格不出现被裁的列；列按优先级显式丢弃，并保留关键操作入口。
3. 导航表面单一状态、互斥、可关闭，且侧栏高亮 = URL = 屏幕内容三者一致。
4. 修掉 1.5 表中的 D1–D10。
5. 每个目标都有可自动断言的验收门禁（见第 6 节）。

**非目标**

- 不改 API 契约、不改数据库 schema（保持 V13）、不改导入/检索的业务字段语义。
- 不引入 UI 框架、CSS-in-JS 或构建期 PostCSS 插件；继续用现有 `src/workspace.css` 结构与原生媒体查询。
- 不重做设计图视觉方向（22 张图仍是唯一视觉基准，本轮只解决尺度与适配）。
- 不为通过测试回退既有新结构。

## 3. 方案 A：响应式尺度系统

### 3.1 断点分档表

以 1536×1024 设计基准为 XL 档（数值保持现状），向下分档。媒体查询按 `max-width` **降序**书写，窄档最后生效。

| 档位 | 视口宽度 | 典型场景 | 主标题 | 副标题 | 侧栏 | 导航项 | 表头 | 数据行 | 列表头像 | 详情头像 | 抽屉宽 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| XL | ≥1920 | 1920×1080、2560×1440、4K | 34 | 16 | 208 | 46 / 16 | 47 / 16 | 72 | 52 | 100 | 500 |
| L | 1600–1919 | 1600×900、1680×1050 | 32 | 15 | 208 | 44 / 15 | 44 / 15 | 68 | 48 | 96 | 500 |
| M | 1366–1599 | 1366×768、1440×900、1536×864 | 28 | 14 | 200 | 40 / 15 | 42 / 14 | 62 | 44 | 88 | 460 |
| S | 1152–1365 | 1280×720、1366×768@125%（1093） | 26 | 14 | 72（图标栏） | 38 / 14 | 40 / 14 | 58 | 40 | 84 | 全宽覆盖 |
| XS | 1024–1151 | 1024×768、1280×800@125% | 24 | 13 | 72（图标栏） | 36 / 14 | 38 / 13 | 56 | 36 | 80 | 全宽覆盖 |
| 平板 | 721–1023 | 768×1024、820×1180 | 22 | 13 | 64（图标栏） | 34 / 13 | 36 / 13 | 54 | 36 | 72 | 全宽覆盖 |
| 手机 | ≤720 | 390×844 | 20 | 12 | 抽屉式 | 34 / 13 | 36 / 13 | 卡片列表 | 40 | 64 | 全屏 |

硬性下限：正文最小 `13px`，元信息最小 `12px`，正文与背景对比度 ≥ 4.5:1（延续 `docs/UI_DESIGN.md` 既有底线）。缩档只作用于「大元素」（标题、头像、行高、内边距、抽屉宽），不把正文压到 13px 以下。

常见分辨率换算（用于验收选点）：1920×1080@125% = 1536×864；1920×1080@150% = 1280×720；1366×768@125% = 1093×614；2560×1440@150% = 1707×960。

### 3.2 实现方式

1. 在 `src/workspace.css` 的 `:root` 引入尺度 token：`--tw-h1`、`--tw-subtitle`、`--tw-sidebar-w`、`--tw-nav-h`、`--tw-nav-fs`、`--tw-table-head-h`、`--tw-row-h`、`--tw-avatar`、`--tw-avatar-lg`、`--tw-drawer-w`、`--tw-card-pad`、`--tw-body-fs`、`--tw-meta-fs`。
2. 现有规则改为引用 token；各档位块只覆盖 token，不再逐条重抄选择器。
3. 新增末尾段落「第十二轮：断点尺度与列优先级」，集中放 `@media` 覆盖块，便于评审和回滚（沿用第十一轮的集中覆盖惯例）。
4. 断点值一律使用 CSS 视口宽度（`window.innerWidth`），与验收脚本的 `setViewportSize` 一一对应，避免出现「脚本测的档位和 CSS 生效档位不一致」。

### 3.3 垂直空间（"模块太大"的直接治理）

- 页面头部：主标题行高与上下内边距按档位收缩（XL 24/28 → XS 14/16）。
- 卡片：`--tw-card-pad` 由 `20px` 降到 `16px`（M 档起），卡片间距 `20px → 14px`。
- 工作台指标卡：≥1366 四列；1024–1365 两列；≤720 一列。单卡最小高度 96px（XL）/ 88px（M 及以下）。
- 筛选 chips 行、搜索框与表格之间的间距按档位收缩，保证首屏可见数据行数（见验收 G1）。

### 3.4 列优先级表（候选人列表；职位/成员/检索结果表同规则）

实现使用现有稳定类名（`.tw-col-select`、`.tw-col-tags`、`.tw-col-time`、`.tw-col-actions`），本轮为「关联职位」「人才库分组」补 `tw-col-positions`、`tw-col-pools`；**不再使用 `nth-child` 序号**（现有并排块用序号，脆弱且易与列增删冲突）。

| 列 | XL | L | M | S | XS | 平板 | 手机 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 复选框 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 姓名 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 最近职位 / 公司 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 关联职位 | ✓ | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ |
| 人才库分组 | ✓ | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ |
| 地点 / 学历 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 标签 | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ | ✗ |
| 更新时间 | ✓ | ✓ | ✓ | ✗ | ✗ | ✗ | ✗ |
| 操作 | 悬停 | 悬停 | 悬停 | 常显 | 常显 | 常显 | 常显 |

并排详情抽屉（≥1440）下的可用宽度 = 视口 − 侧栏 − 抽屉 − 内容内边距（40）：

- **≥1600**（可用 ≥872）：隐藏 `标签`、`更新时间`；保留 姓名 / 最近职位 / 关联职位 / 人才库 / 地点学历 / 操作。
- **1440–1599**（可用 712–807）：再隐藏 `关联职位`；保留 姓名 / 最近职位 / 人才库 / 地点学历 / 操作。
- 抽屉宽度取 `--tw-drawer-w`（XL/L 500、M 460）。
- **硬门槛**：任一验收视口下 `table.scrollWidth ≤ 容器 clientWidth + 1`；若某表因内容确实需要横向滚动，必须显示可见滚动条，且默认位置能看到 `操作` 列。

被隐藏列的替代入口：候选人行操作在 S 档及以下改为常显；`标签`、`更新时间`、`人才库分组` 信息仍在详情抽屉与「更多筛选」中可达。

## 4. 方案 B：导航表面单一状态机

### 4.1 状态定义

```ts
type Surface =
  | { kind: "page"; page: NavPage }        // dashboard | candidates | talent-pools | positions | position-detail
  | { kind: "tool"; tool: ToolPageId; from: NavPage }  // assistant | resume-search | attachment-parser
  | { kind: "import"; from: NavPage }
```

用**联合类型**从类型层面排除「两个表面同时为真」，取代当前并列的 `importOpen` / `assistantOpen`。

### 4.2 交互规则

1. 任何时刻只渲染一个表面：主内容栈、工具页、导入页三者互斥。
2. 点击已激活的入口 = 关闭并返回 `from`（记忆进入前的页面）；点击其他入口 = 直接切换，不叠加。
3. 侧栏高亮**由 surface 派生**，不再用 `importOpen` 优先判断。
4. URL 与 surface 一一对应：`/`、`/candidates`、`/talent-pools`、`/positions`、`/positions/:id`、`/assistant`、`/resume-search`、`/attachment-parser`、`/import`；`popstate` 反向映射回 surface。
5. 存在可恢复导入任务时，初始 surface 为 `{ kind: "import" }`（保留现有 `hasRecoverableImportTask` 行为）。
6. 任何导航动作先落地新 surface，再清理抽屉/弹层状态。
7. Esc 优先级：模态 → 抽屉 → 工具/导入（返回 `from`）。

### 4.3 状态同步

- 左侧「候选人库 / 工作台 / 人才库分组 / 职位管理」与表面互斥；`position-detail` 属于 `page`。
- 从检索结果点「查看档案」打开候选人抽屉时，保持当前 tool 表面不变（现有 `openCandidateById` 会误关助手，需要保留 tool 而不清空）。

## 5. 方案 C：其余缺陷修法

| 编号 | 修法 |
| --- | --- |
| D1 | 检索补齐逻辑只在「已有真实命中且不足一页」时启用；无任何真实命中时返回 0 条并给出明确空态。补齐项不得标注「部分匹配」，需要时新增 `condition_status: "padding"` 与 `reasons: ["仅用于补足分页，不代表命中"]`；`score` 改为真实相关性得分或显式 `null`。前端「部分匹配」只在存在非空 `evidence` 时渲染 |
| D2 | 操作列 `white-space: nowrap` + 按钮 `flex: 0 0 auto`；列宽按档位给出下限（两按钮 + 间距 + 右侧内边距 ≥ 132px），或改为「编辑」+ 图标按钮 |
| D3 | 标签列仅 XL/L 显示（见 3.4）；chip 容器 `flex-wrap: nowrap` + `overflow: hidden`，最多 2 个 chip + `+n`；同一列表所有行等高（验收 G3） |
| D4 | 把「显示」按钮收回卡片内容区（`grid` 增加第三列或放入值容器），保证 `按钮右边界 ≤ 卡片右边界 − 内边距` |
| D5/D6 | 统一弹层管理：抽出一个 `useDismissableLayer`（Esc + 点击外部 + 路由/表面切换时关闭），删除 `src/App.tsx` 中监听 `.menu-wrap` 的失效逻辑；导出菜单、更多筛选、模态框、选择器统一接入 |
| D7 | 分组名加 `title` 并在悬停/聚焦时展示完整名称；左栏最小宽度按档位给出，名称区域不再压到 99px |
| D8 | 统一命名：侧栏与页面标题统一为「履历检索」「AI 助手」；附件解析页按钮改为「返回人才库」；弹窗标题改为「新建分组」 |
| D9 | 工作台指标卡文案改为「人才库分组（使用中）」，或在卡片副标题标注口径 |
| D10 | 二选一：桌面端恢复顶栏助手入口（推荐，与文档一致），或修改 `docs/UI_DESIGN.md` 改为「仅侧栏与移动端顶部栏」。本轮按恢复入口实施 |

## 7. 风险、兼容与回滚
