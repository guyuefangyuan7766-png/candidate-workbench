# 候选人入职信息与北森数据清理设计

## 背景

北森导出的申请数据包含 `入职状态` 和 `入职日期`。当前系统只把这类流程字段保留在来源原始载荷中，候选人主表没有可查询、可编辑、可展示的对应字段。现有 `candidate_preferences.employment_status` 表示求职偏好，旧 `candidates.stage` 表示兼容性的招聘阶段，二者都不能承载实际入职记录。

## 目标

1. 在候选人主表增加 `hire_status` 和 `hire_date`，通过 API、通用导入、北森导入和导出完整传递。
2. 在候选人档案的编辑表单和详情页显示、编辑这两个字段。
3. 对用户提供的 7 个 BIFF8 `.xls` 文件逐文件生成 `.xlsx` 副本，只保留入职状态有业务值的行。
4. 同步开发所需的文档链：数据模型、API、字段映射、导入指南、测试说明、README、版本变更记录和迭代日志，明确新字段与旧阶段/求职偏好的边界。

## 非目标

- 不把 `stage = 已入职` 自动迁移为 `hire_status`。
- 不把 `candidate_preferences.employment_status` 重命名、删除或改义。
- 不新增入职审批、入职流程、状态枚举管理或按入职状态筛选 UI。
- 不修改原始 `.xls` 文件，不合并 7 个源文件为额外汇总文件。

## 数据模型

`candidates` 增加两个可空列：

- `hire_status TEXT`：来源系统提供的入职状态文本，保留非空原文，最大 200 个字符。
- `hire_date TEXT`：规范化为 `YYYY-MM-DD` 的有效日期；允许未来日期，允许状态有值但日期为空。

新数据库在基础 `CREATE TABLE` 中直接包含列；已有数据库通过幂等 V11 迁移 `ensureColumn` 补列，并建立 `candidates_hire_status_idx` 与 `candidates_hire_date_idx`。迁移不重建或清空候选人表。

## 导入与校验

- 通用表格字段别名识别 `入职状态`、`hire_status`、`hire status` 以及 `入职日期`、`hire_date`、`hire date`。
- 北森专用映射识别精确表头 `入职状态` 和 `入职日期`，并在同一候选人跨批次导入时遵循现有“非空覆盖、空值不清除”规则。
- `hire_status` 仅做去首尾空白和长度校验，不强制枚举，避免丢失北森未来新增状态。
- `hire_date` 接受 ISO、斜线和中文年月日形式，校验真实日历日期并输出 `YYYY-MM-DD`；不以当前日期限制未来入职安排。
- 清理文件把空白文本、空单元格和精确文本 `空` 视为空状态；其他状态（当前样本为 `已入职`、`已离职`、`已转正`、`已取消入职`、`待入职`）原样保留。清理不会因日期为空而删除行。

## UI

沿用现有 CandidateForm 的分区式布局：在“求职偏好”后增加“入职信息”分组，提供带可见标签的状态文本输入和日期输入；空值可保存为未填写。CandidateDrawer 的“档案”页在求职偏好附近显示状态和日期，日期使用现有 `formatDate` 展示。详情字段加入动态活动字段中文标签，保持现有可访问标签、按钮和响应式网格。

## Excel 输出

每个源文件输出一个同名后缀 `_已整理.xlsx` 的工作簿，保留工作表名 `应聘者申请数据` 和三列顺序 `入职状态`、`入职日期`、`应聘者ID`。状态写入文本，日期写入可排序的日期值并使用 `yyyy-mm-dd` 格式，首行冻结并保留清晰的表头样式。输出目录使用本次任务专用 `outputs/2026-08-21-hire-status-cleaned/`，原始文件不覆盖。

## 验证

- 后端测试覆盖 V11 迁移幂等性、POST/PATCH 校验、未来/非法日期、北森字段导入、通用字段映射和导出字段。
- 前端构建和档案源码测试确认编辑回填、提交 payload、详情标签存在。
- 清理脚本逐文件验证：工作表/表头一致、输出行的状态均非空且不为 `空`、行数与保留统计一致、ID 和日期值未错位。
- 使用 artifact-tool 检查输出工作簿关键区域、扫描公式错误并渲染每个工作表做视觉核验。
- 在 `CHANGELOG.md`、`docs/ITERATION_LOG.md`、`docs/DATA_MODEL.md`、`docs/API.md`、`docs/FIELD_MAPPING.md`、`docs/IMPORT_GUIDE.md`、`docs/TESTING.md` 和 `README.md` 中记录版本/功能变化、迁移、接口字段、导入规则、验证命令和已知限制。
