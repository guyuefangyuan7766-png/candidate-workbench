# 候选人入职信息扩展 V12 设计

## 背景

V11 已把候选人的入职状态和入职日期贯通到主表、导入、档案和导出。对新的北森人才库文件复核后发现，源文件还提供“入职职位”，但没有精确的“入职状态”表头；如果只丢弃该职位或把“入职雇佣关系”误当状态，都会损失来源事实。

## 目标

1. 在候选人主档新增 `hire_position`，并与 `hire_status`、`hire_date` 一起贯通 CRUD、通用/北森导入、档案编辑/详情和 CSV/XLSX 导出。
2. 对缺少状态但有日期的来源行补足可查询状态 `不确定`，同时保留原始行和原始“入职雇佣关系”在来源快照中。
3. 三项入职信息全为空时不渲染档案中的“入职信息”区块；候选人本身仍保留在人才库、列表和搜索中。
4. 导入验收同时核对人才库关系、来源历史和职位关系；北森的“最后职位类投递的职位id”是关联职位键，必须建立 `candidate_positions` 关系。它在实际文件中可能呈现职位名称文本：先用候选人 ID 和最后投递时间解析唯一历史职位，未命中时才把该值作为稳定来源键和草稿标题；没有该值的行不凭“职位编号”或“入职职位”猜测关联职位。

## 非目标

- 不把 `candidate_preferences.employment_status`、`candidates.stage` 或 `入职雇佣关系` 改名/迁移为 `hire_status`。
- 不新增入职审批、流程引擎、状态枚举管理或入职筛选器。
- 不因三项入职信息为空而删除或隐藏候选人主记录。
- 不修改原始 `.xls` 文件，不把临时验证 CSV/XLSX 当作正式交付源文件。

## 数据模型与版本

V12 通过幂等加法迁移给 `candidates` 增加：

- `hire_position TEXT`：来源系统入职职位文本，去首尾空白，最多 300 个字符。
- `hire_status TEXT`：来源状态文本，去首尾空白，最多 200 个字符；日期非空且状态为空时规范化为 `不确定`。
- `hire_date TEXT`：真实日期规范为 `YYYY-MM-DD`，允许未来日期。

V11 已存在的状态/日期列和数据保持不变；V12 只补列（旧库）和索引，不重建或清空候选人。为 V12 新增 `candidates_hire_position_idx`，保留 V11 的两个索引。迁移记录为 `(12, 'candidate_hire_information')`，重复启动只保留一条记录。

## 字段与导入规则

通用和北森轮廓识别：

| 目标字段 | 表头别名 | 规范化 |
| --- | --- | --- |
| `hire_position` | `入职职位`、`入职岗位`、`hire_position`、`hire position` | trim，非空最多 300 字符 |
| `hire_status` | `入职状态`、`入职情况`、`hire_status`、`hire status` | trim，非空最多 200 字符；日期非空且结果为空时写 `不确定` |
| `hire_date` | `入职日期`、`入职时间`、`hire_date`、`hire date` | 真实日期，输出 `YYYY-MM-DD` |

增量导入遵循非空覆盖、空值不清除：空的入职职位/状态/日期不会抹除已有值；非空日期触发状态兜底时，仅在该候选人的有效状态仍为空时写入 `不确定`。原始 `入职雇佣关系` 继续只进入来源 `raw_payload`，不投影为状态。

职位关系按以下优先级解析：`申请ID` 仍只用于申请来源血缘；只要工作簿存在北森字段“最后职位类投递的职位id”，该字段就是整份工作簿唯一权威的 `position_source_record_id`/`position_external_code` 来源。某行该值为空时不使用同一行的普通 `职位编号` 或 `职位名称` 建立关系；只有整份工作簿完全没有该专用表头时，普通 `职位编号` 才作为兼容回退键。专用字段为显示名时先结合候选人 ID 与“最后职位类投递时间”解析唯一历史职位，未命中才以该值创建稳定草稿。`入职职位` 只记录入职事实，永远不作为关联职位键。

人才库列按现有北森规则合并、去重并建立 `candidate_talent_pools` 关系；来源列按 `effective/first/last` 规则写入候选人来源历史。导入验收必须检查至少一条人才库关系和一条来源历史，并确认没有明确职位键时 `candidate_positions`/申请来源不被错误创建。

## UI 与导出

CandidateForm 在“入职信息”分区提供状态、日期、职位三个可见标签控件。CandidateDrawer 仅在三项任一非空时渲染该分区；详情字段标签和导出标题使用“入职状态”“入职日期”“入职职位”。旧 API 响应缺少新列时前端按空值兼容。

## 验证与验收

- TDD 覆盖 V12 迁移幂等、状态兜底、职位字段 CRUD/导入/导出、三项全空的条件 UI，以及人才库/来源/“最后职位类投递的职位id”职位关系导入语义。
- 真实文件先只读解析：191 列、10,000 行、精确 `应聘者ID`；从 135 条有日期记录中选取 100 条通过现有校验的行。正式提交后核对 100 条 `hire_position`/`hire_date`、100 条 `hire_status=不确定`、人才库关系、来源历史，以及所有非空“最后职位类投递的职位id”行的 `candidate_positions` 关系；该字段为空的行不创建职位关系。
- 运行 focused/full tests、`npm run build`、`git diff --check`，并记录服务健康检查和导入批次证据；不把敏感原始 payload 写入公开文档。
