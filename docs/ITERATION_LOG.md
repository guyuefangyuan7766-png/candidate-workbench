## 2026-08-12 - 0.1.1 附件身份占位与数字噪声修复

### 目标

修复文本简历中“手机号：未提取 + 唯一匹配邮箱”仍被判定为多个身份的问题，并把附件身份规则、版本和验收状态同步到维护文档。

### 范围与完成项

- 确认根因有两层：PDF/DOCX 文本层可能拆开“手机/邮箱”标签；通用标签扫描器还会把“项目邮箱：…”等正文短语识别为第二个身份字段，标签值段又可能吞入后续正文邮箱，最终触发多身份
- 使用现场 PDF 的隔离源文件重放后确认另一条根因：真实字段使用“移动电话”，旧规则未识别该标签，全文兜底又把知乎链接中的 11 位文章编号当作第二个中国手机号；现已识别“移动电话”和 PDF 行内分隔身份标签，只读取标签字段值
- 修复批次恢复状态：待确认项引用的短期预览已过期、取消、失败或丢失时，启动恢复会将其转成明确失败并要求重新上传，不再继续展示不可提交的旧匹配结论
- 在服务端附件身份规范化边界过滤 `null`、空字符串、纯空白和精确的“未提取”；手机号与邮箱分别格式验证、规范化、去重后再统计唯一值
- 区分“身份标签存在但值缺失”和“文档没有该身份标签”：前者保持缺失，后者才执行受限全文兜底；无标签手机号兜底只接受中国大陆手机号或显式国际号码。标签值在同一行遇到下一个字段冒号时截断
- 中文身份标签允许 PDF/DOCX 提取造成的内部空格/换行；行内标签要求明确字段边界，并限制可嵌入识别的完整标签，避免从“项目邮箱”等正文短语中间命中
- UI 继续只根据空 API 值展示“未提取”，不把占位文案写回身份字段；API 公共记录不暴露内部候选值数组
- 增加 UTF-8 TXT 单文件和批量附件支持；保留 PDF、DOCX、XLSX、XLSM、BIFF8 XLS、UTF-8 CSV、安全校验、确认事务、一次性令牌与 SHA-256 幂等行为
- 应用版本更新为 `0.1.1`；不新增 schema 迁移，不批量覆盖真实数据库历史原始数据

### 验证结果

- `node --test tests/backend/attachments-v6.test.mjs`：30/30 通过，覆盖“项目邮箱”正文噪声、单行文本、空格/换行标签和真实双手机号歧义
- 附件批量、UI 和中文文件名相关测试：24/24 通过
- 完整 `npm test`：320 项中 319 通过、0 失败、1 项按设计跳过；预期故障注入日志不计为失败
- `npm run build`：TypeScript 与 Vite 生产构建通过，1,855 modules；保留现有主 chunk 大于 500 kB 提示
- Playwright CLI `0.1.18`、Node.js `v24.18.0`，使用 `output/playwright/attachment-identity-011/e2e.db` 和独立端口 `4491`；只写入虚构候选人和虚构 TXT，模型配置在隔离进程中禁用
- 浏览器确认“手机：未提取”与唯一邮箱得到“单一身份字段唯一匹配”，日期、版本号和项目序号未制造身份歧义；中文 TXT 文件名在保存记录和下载入口中完整显示
- 390×844 下 `innerWidth`、`body.scrollWidth` 和根节点 `scrollWidth` 均为 390；截图人工检查无控件重叠，本地工作台页面 console 0 error/0 warning，隔离服务 stderr 为空
- 浏览器会话已关闭，隔离服务已停止，端口 `4491` 已释放；正式数据库未用于上传、确认、截图或测试写入
- 正式旧 PID `8024` 正常终止并释放 `4173`；当前 `master` 工作区服务以显式 `data/recruitment.db` 启动为 PID `21232`，只监听 `127.0.0.1:4173`
- 正式服务仅只读请求 `/api/health` 与 `/api/agent/status`：health 为 `ok`，Agent 模型为 `kimi-k3`，`configured`、`full_readonly`、`async_tasks` 均为 true；未执行正式候选人内容查询或业务写入

### 关键决策

- 不对姓名、备注、履历正文等普通字段做宽泛字符串替换；占位过滤只作用于附件身份字段边界
- 不后台改写修复前生成的预览。旧预览在部署后应取消或放弃，并重新上传原附件生成新预览

### 遗留问题与下一步

- 修复前已生成的错误预览不会自动升级；使用者需在当前服务中重新上传原附件
