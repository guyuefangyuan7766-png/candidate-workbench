# 拾才工作台：人才检索与前端实现交付

本文件保留首次 0.2.0 本地模式发布时的事实。用户随后授权正式混合检索，最新回填、启用、修复及指标见 [0.2.0 / V13 补充交付](2026-09-10-search-hybrid-formal-supplement.md)；下文“当前关闭”等措辞指本次补充前。

日期：2026-09-10。用户在方案后明确要求直接执行，完成代码与合成匿名验收后又授权应用并启动正式服务。**当前应用0.2.0已正式启动，数据库保持V13；本地检索改进和新界面生效，远程检索仍关闭，未生成真实简历向量。** 完整混合交互的延迟门禁未通过。备份、fresh构建、健康/静态资源/限定合成ID检索及schema核验见 [正式部署记录](../evidence/search-formal-deployment.json)。下文保留匿名验收及未通过项的实际结论。

## 已落地行为

- React/TypeScript、Express、SQLite架构保留。应用人才检索GET/POST与注入的Agent人才检索工具共用新执行器，通用全业务记录搜索保持原接口。
- 查询计划经Ajv完整Schema和语义校验。保留AND/OR、局部NOT、排除、精确短语、年限包含/不包含上下界、当前/意向地点、阶段、关系筛选、偏好与未解析条件。模型不能提供SQL，显式筛选由服务端保持；不确定条件标成partial，不静默变成硬过滤。
- 固定SQL先计算候选人资格，随后FTS5和向量召回。修复先限制命中文档再过滤的漏召回，跨记录交集按候选人求值，同记录约束单独执行；未知年限不满足明确年限要求。
- 资格/排除不受向量分数和重排改变。主档字符串技能标签、本人工作/项目/技能区块、已确认简历附件可供本人证据；关联职位/人才库另标为related，任意来源JSON对象不能证明本人能力。
- 候选人级RRF首轮最多400人，重排前50人；重排在分页前执行。完整资格集合仍可深分页，400不是总数上限。游标保存当前页/下一页和排序快照，绑定筛选、数据库修改和向量代际；变化或过期返回409并允许重新检索。
- 语义命中的有效本人片段进入重排包和结果证据，显示“语义相关”，不显示能力百分比。片段使用原文偏移；分页再次校验当前来源哈希，过期片段不展示。
- SQLite向量元数据、Float32及USearch HNSW使用独立目录、不可变代际与原子manifest。默认1024维，模型/维度/切片版本隔离；600字符切片、80字符重叠、内容去重和Embedding缓存，未变化材料零新增Embedding。删除/归档维护prune，查询资格和来源复核立即排除失效事实，失败/取消保留active代际。

## 前端范围与组件判定

八个既有入口、导航顺序、页面用途、列表/按职位模式、select筛选、归档范围和业务功能保留。`src/App.tsx`与开始时用户未提交版本的SHA-256完全一致；没有新增主入口、工作流、向导、条件编排器或必经确认步骤。

继续输入框加结果。新增默认折叠的条件摘要、可展开证据、非阻塞降级/完整性提示、取消、重试、IME保护，以及请求序号和AbortController防迟到覆盖。职位/人才库选项从独立完整分页接口加载，不再受外围第一页列表限制。调整字号、间距、按钮、长文本换行、表格容器滚动和移动布局。

实测并修复768px菜单断点不一致、移动候选人页顶部预留被覆盖、检索/附件页绝对header盖正文。**没有删除组件**；正常关闭弹窗、折叠、tabs、无障碍元素及响应式组件保留。只有已证实重复、无用途且遮挡、并有完整功能承接时才应删除，本轮没有符合该标准的组件。

## 已验证模型契约和取舍

详见 [匿名网关契约](../evidence/search-gateway-contract.json)。没有记录网关地址、密钥、原始上游错误正文或真实候选人材料。

| 能力 | 实际契约 |
| --- | --- |
| Embedding | `POST /v1/embeddings`，`text-embedding-v4`，默认1024维、显式512维通过，batch10成功、11因批量上限返回400；按data[].index还原顺序 |
| Rerank | `POST /v1/rerank`，`qwen3-rerank`，documents/query/top_n，返回results[].index/relevance_score；实测50条，无重复或缺失索引 |
| 规划 | `gpt-6-astra`接受严格response_format.json_schema结构子集；完整draft2020直接提交返回400。适配器转换为已验证子集，本地仍以完整Schema强制验证，不改用json_object |

默认规划30秒、Embedding/Rerank每请求5秒，查询worker最多并发2、总45秒、浏览器48秒。`SEARCH_QUERY_TIMEOUT_MS`只能缩短规划预算。原18秒总体/10秒p95目标未达；预算调整是隔离验收配置，不是通过原性能门禁。其他聊天模型未因“模型列表可见”而被认定具备Embedding/严格Schema/Rerank能力。

模型在远端运行，本机承担SQLite和向量存储/评分，不要求本地GPU。查询规划仅发送查询文本；维护发送选定本人材料，重排最多50个、每人1800字符的本人证据包。本轮全部内容均为合成匿名文本；未来真实材料仍可能含正文中的个人信息，正式外发范围、保存策略与供应商费用须另行落实，不能把字段白名单当成全文脱敏。

## 实际质量和性能

固定80位合成人才、60条不同查询，覆盖用户指定六例及多种年限边界、城市、OR与排除组合。相关性由独立事实规则标注，当前为二元标注；不是生产分布或业务专家0–3等级标注。每次评测使用新建临时数据库。最终远程运行并发2，真实调用规划60次、Embedding62次/75条文本（含建索引与查询）、Rerank60次。

| 指标 | 原检索基线 | 修复后的本地检索 | 真实混合链路（含回退） |
| --- | ---: | ---: | ---: |
| 条件计划正确率 | 六例故障复现0/6；未给60例旧计划评分 | 100% | 100% |
| Recall@50 | 0.2167 | 1.0000 | 1.0000 |
| Precision@10（固定除10） | 0.1250 | 0.5067 | 0.5067 |
| nDCG@10 | 0.1794 | 1.0000 | 1.0000 |
| MRR | 0.1958 | 1.0000 | 1.0000 |
| 证据归属准确率 | 未测 | 100% | 100% |
| 延迟p50 | 1.54ms | 6.08ms | 7,414.86ms |
| 延迟p95 | 10.01ms | 14.74ms | 24,501.32ms |
| 查询结束采样最高RSS | 未单独采样 | 100,814,848字节 | 91,611,136字节 |

实际模型计划直接通过46/60=76.67%，14次规则回退单独记录；不能把总体100%条件正确率称为模型自身100%。回退原因包含超时、输出校验和确定条件/覆盖校验拒绝。语义与重排已实际调用，正确规则+FTS在此简单语料上已达到指标上限，**本结果没有证明向量相对修复FTS的额外质量收益**。

8条至少有10个正例的标准子集Precision@10为1.00（旧基线0.4375）；其他查询正例稀疏，固定除10，因此总体0.5067不等于约一半返回人选不相关。当前60条无零正例查询；空结果另由匿名回归和浏览器测试覆盖。评测工具为将来零正例明确使用Recall/nDCG/MRR=N/A，保留零结果正确率。旧轮次曾按JSON属性顺序误判条件，最终已修正比较方法、补测试并重跑，实际/标注计划存于报告，旧错误成绩不用于结论。

证据：[本地60条](../evidence/search-hybrid-anonymous-local.json)、[远程60条](../evidence/search-hybrid-anonymous-remote.json)。RSS为明确采样点的观测值，可能错过瞬时峰值；没有把它当全进程100ms连续峰值。未采集供应商计费金额，不编造价格。

容量结果见 [本地1万/10万](../evidence/search-hybrid-capacity.json) 与 [10万向量512/1024维](../evidence/search-vector-capacity.json)。最终代码的1万/10万合成主档本地查询p95分别146.33/1,621.85ms，5次新worker约314–372/1,675–1,856ms，数据库12,763,136/122,335,232字节。向量实验使用确定性低内在维数数值向量：512维构建采样峰值777,605,120字节，1024维1,223,442,432字节；SQLite/ANN分别465,240,064/219,637,488和515,555,328/424,437,488字节。10000个资格向量精确评分p95约954/952ms。它只验证容量与绑定可用性，不能代表10万真实履历语义质量、ANN Recall或60万切片的内存容量。新进程测试未清OS磁盘缓存。

- 最终新增/受影响定向测试76/76通过，含400窗口之外530人深分页无重复/遗漏；构建、类型、语法、差异检查通过。构建仍提示已有约704KB主包大于500KB。
- 完整测试实际661项：646通过、8失败、7跳过；8项在原工作树55项子集中复现。涉及已有storage_path政策、历史V11文档断言及缺失V12辅助文件；未回滚用户修改。完整成绩先于最后定向修复，不声明最终全套已通过。

- 1440×900、768×1024、390×844共69/69浏览器断言通过。8入口、列表/按职位、筛选/归档、详情、证据键盘操作、取消/迟到、重试、分页和长文本覆盖，正常控制台错误/警告、页面异常、意外HTTP错误均0。预期503/409注入单列；36张匿名截图。见 [界面验收](../evidence/search-ui-acceptance.md)。没有历史像素基线，不宣称像素回归或完整屏幕阅读器审计。

## 回退和仍未通过的依赖

运行时`SEARCH_REMOTE_ENABLED=false`保持新规则/固定资格/FTS检索。规划、向量或重排失败分别保留安全本地结果与非阻塞提示；不能撤销硬条件换取结果数量。损坏/空间不兼容索引不会被加载。索引构建失败不会切换active；旧代际可由明确维护操作重新指定并复验，当前没有正式数据自动回填或自动清理任务。

当前仍未通过完整混合p95≤10秒/总18秒门禁；需要更快且通过相同Schema/匿名质量测试的规划模型，或在后续明确调整性能目标。业务专家qrels复核、0–3等级相关性、多样长简历语料、512与1024质量对照、ANN精确oracle召回、供应商模型版本/漂移canary、保留策略/费用，以及真实库增量维护和正式回填都未被本轮有限匿名验收替代。**本轮代码与匿名联调已交付，不标记正式混合检索上线或全部方案门禁完成。**

原工作区未提交修改按开始指纹逐项核对，仅带回本轮差异；无关文件不覆盖、不回滚。整合前备份与文件哈希见 `docs/evidence/search-integration-manifest.json`。
