# 人才检索与前端视觉优化交接文档

日期：2026-09-10
状态：方案已确认，尚未实施、迁移或部署。
项目：拾才工作台（React + TypeScript + Express + SQLite，个人本机版）

## 1. 本轮目标

优先处理两类问题：

1. 人才检索准确性：模型理解 + 结构化过滤 + SQLite FTS5 + Embedding + Rerank 的混合检索。
2. 现有前端视觉与检索结果体验优化。

本轮只完成了代码和文档调查、方案讨论以及网关模型列表查询，没有修改业务代码、数据库、迁移或部署服务。

## 2. 用户已经确认的硬约束

- 必须保持 Gemini/GPT 式“输入框 + 结果”交互。
- 绝对不能改成工作流、步骤向导、条件编排器、多阶段确认页面。
- 用户输入后直接得到结果；查询理解、向量召回、过滤和重排在后台完成。
- 不改变候选人库、人才库分组、职位管理、工作台和主入口的导航、入口数量、页面用途、展示模式、筛选方式和既有业务功能。
- 不处理此前痛点清单中的“问题101：功能面大、入口较多”。
- 可以在现有页面上改善视觉和增加直接服务于检索的功能，但不能改变默认操作习惯或增加必经步骤。
- 正常弹窗、折叠内容、标签页、无障碍元素和响应式隐藏组件不能因为“隐藏”而删除。
- 只有确认无实际用途、重复挂载或已经被完整替代且造成遮挡/重叠的组件才允许删除。
- 真实数据、正式库索引回填、数据库迁移和生产部署另行安排。

## 5. 推荐技术方案

### 查询理解

新增独立查询计划模块，例如 `server/search-query-plan.js`。模型输出严格 JSON Schema；模型只输出查询计划，不能输出 SQL。规则解析器作为兜底，保留 `must`、`should`、`must_not`、年限、地点、职位、人才库、来源和 `unresolved`。

### 混合召回

```text
输入框
 -> 模型/规则查询计划
 -> 结构化硬过滤
 -> FTS5 精确召回 + Embedding 语义召回
 -> 候选人级去重和 RRF 融合
 -> 硬条件校验
 -> 有界 Rerank
 -> 结果和业务证据
```

- 结构化条件负责资格约束。
- FTS5 负责精确词、中文原词、技术名词和短语。
- Embedding 只补充语义相近的本人经历。
- Rerank 只处理有界候选证据。
- `must_not` 和硬过滤不能被向量相似度抵消。
- 关联职位、人才库描述与候选人本人履历必须分开计分和展示。
- 修复先截断 FTS rowid 再过滤候选人的路径。
- 排序分数不得展示为能力百分比。

### 向量数据

- 仅为候选人主档、教育/经历/项目/技能区块和附件履历正文切片。
- 不把关联职位、人才库描述、活动和导入批次作为能力向量。
- 建议 400-800 中文字符、10%-15% 重叠，记录 `candidate_id`、文档来源、内容哈希和索引版本。
- 先用匿名数据评估现有向量表的有界计算，再决定正式 HNSW 或其他本地索引。
- 不在十万级数据上用 Node.js 数组做无界全量暴力计算。

### 前端

- 继续保持输入框、筛选项、结果列表和证据展开。
- 可增加非阻塞的已识别条件摘要、结果完整性提示、降级提示、重试和证据说明。
- 不增加强制查询计划确认、工作流、向导或新的主页面。
- 结果使用“工作经历、项目经历、附件简历、关联职位”等业务名称，不显示表名、字段路径、BM25、向量距离或内部实体类型。
- 优化字体、间距、色彩、边框、按钮和加载/空结果/错误状态。
- 审计并删除真正重复、无用途且造成遮挡的组件；不得误删正常隐藏和无障碍组件。

## 6. 建议实施顺序

1. 只读探针确认 Embedding、Rerank、严格 JSON Schema 的请求/响应契约。
2. 建立查询计划和规则解析回归测试。
3. 修复 FTS5 候选人级完整召回、交集、排除和分页。
4. 接入 `text-embedding-v4`，先在匿名数据生成和评估向量。
5. 接入 `qwen3-rerank`，只对有界候选证据重排。
6. 改造结果业务化展示和错误/降级状态，保持输入框加结果。
7. 审计 `src/preview-theme.css`、抽屉和响应式布局，修复遮挡和重叠。
8. 运行检索评测、`npm test`、构建、桌面/390px 浏览器验收和可访问性检查。

## 7. 评测标准

建立至少 60 条匿名查询，覆盖中文岗位词、AND/OR/NOT、年限、地点、精确短语、跨记录交集、关联职位伪命中、归档过滤和分页。

必须记录：条件解析准确率、Recall@50、Precision@10、nDCG@10、MRR、证据归属准确率、p50/p95、内存、索引体积和降级成功率。所有结果必须实际执行后报告。

前端验收覆盖原有入口和功能不变、输入框加结果模式不变、1440px/768px/390px 视口、无关键控制台错误、无意外遮挡、键盘焦点可见和无水平溢出。
